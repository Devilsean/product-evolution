# 04 机会发现与创新（Opportunity Discovery）

这是本 Skill 与他类"体验审计"的分水岭。

诊断回答"哪里不好用"，机会回答"还可以是什么"。后者不来自当前 PRD，来自对用户任务和产品能力的重新组织。

原则：**所有机会都是假设（E3）**，必须写明反证条件，不得写成"用户需要"。

---

## 一、两条通道

### 通道 A：从摩擦反推形态

对每个高影响问题，不要问"怎么修"，问三个问题：

1. 这个摩擦是不是因为流程被设计成了这样？换个顺序还存在吗？
2. 如果这一步完全由 AI 代做，用户的角色会变成什么？
3. 如果这一步被彻底删掉，用户会损失什么？（如果什么都损失不了，就应该删）

### 通道 B：从能力重组出新价值

把产品已有的数据和能力列成两列，交叉配对：

| 已有能力 | 已有数据 |
|---|---|
| 基础资料管理 | 分类、属性、关联条目 |
| 报表生成 | 查询配置、字段定义 |
| 文档编辑 | 正文、历史版本 |

配对后问："A 的产出能不能成为 B 的输入，且用户不用重复劳动？"

例：字段定义 × 正文 → 生成时的一致性校验；查询配置 × 历史版本 → 口径变更提醒；这类组合通常是产品最容易被忽视的差异化来源。

---

## 二、第三条路径：任务重构（真正跳出 PRD 的方法）

> 状态：**（候选）**。来自设计推导，尚未在 ≥2 个产品上复现。可按此执行，但不得当作已验证方法引用，也不得写进验收结论。

前两条通道仍以当前产品为起点，容易只在原地打转。第三条从**用户想达成的事**出发，完全不看现有功能结构。

五步：

1. **写下一句用户目标**，要具体到可交付："我想在两周内写出能给人看的前三章。"
2. **列出产品当前要求用户做的全部动作**，按真实顺序编号（从打开到拿到成品）。
3. **给每个动作打标**：`只有用户能做` / `机器能做` / `可以不做`。
4. **重画流程**：机器能做的交给机器，可以不做的不做，剩下的才需要界面。
5. **与现状对比**，差异处即机会。

判据：

- 重画后只差 1-2 步 → 这是优化，走 03/05，不要包装成创新。
- 差一个数量级（12 步变 3 步），或用户角色变化（从"逐条操作者"变成"批量审阅者"），才是产品级机会。
- 重画不出来的部分，往往就是产品真正的价值所在——记下来，那是定位。

## 三、七个创新技法

每个技法给一个具体提问句式，直接拿去用。

| 技法 | 提问 | 适用 |
|---|---|---|
| 约束移除 | 如果用户完全不需要做 X，产品还能成立吗？ | 找出被迫的手工劳动 |
| 顺序重排 | 把流程倒过来做会怎样？先给结果再让用户改？ | 降低启动门槛 |
| 场景迁移 | 同一个能力放到移动端/离线/协作/批量场景，还成立吗？ | 找新场景 |
| 极端用户 | 完全不懂的新手、每天用 3 小时的老手，各自最痛的是什么？ | 找分层需求 |
| 能力重组 | 哪个数据被产生后就没再被用过？ | 找被浪费的资产 |
| AI 原生 | 哪一步以前因为"人做太贵"而被迫简化？现在能不能重做？ | AI 产品核心 |
| 形态质疑 | 如果今天从零做，还会做成现在这样吗？会砍掉什么？ | 方向探索模式必做 |

对"人定方向、AI 出成品"这类协作型产品，AI 原生这一条尤其关键：当前的产品结构往往来自"AI 写得慢、写得差、上下文太短"的时代假设，值得整体重审。判断时不要看现在的界面长什么样，要看它默认了 AI 有多弱。

## 四、机会卡片

整体清单按 `references/templates/opportunity-report.md` 组织。单张卡片缺项不算完成：

```
## 机会 N｜标题
来源：通道 A / 通道 B（技法：约束移除）
触发场景：用户在什么情况下会受益（要具体到动作，不是人群标签）
现状：现在这件事怎么做，代价是什么 [E1/E2]
机会：可以变成什么样（一句话，能画出来）
为什么现在可能成立：技术/数据/成本上发生了什么变化
最小验证：花最小代价怎么证实（做原型 / 造一个假按钮看点击 / 用现有数据离线试跑）
反证条件：出现什么现象就说明这个方向是错的  ← 必须有
风险：会不会破坏现有价值、增加认知负担
证据等级：E3
优先级建议：待 05 评估
```

**反证条件**是这个机制的核心。写不出反证条件的机会，说明它只是一个愿望，不是可验证的假设，应退回 OPPORTUNITY_BACKLOG 而不是进入提案。

示例反证：*"如果 5 个真实用户里没人愿意为这个能力多花一步操作，说明痛感不足，应放弃。"*

## 五、数量与取舍

- 一轮探索产出 **3-6 个**机会。少于 3 个说明视角不够，多于 6 个说明没筛。
- 必须至少有一个**跳出当前形态**的机会（否则只是体验优化清单）。
- 必须至少有一个**减法或合并**的方向（否则容易滑向功能堆砌）。
- 明显低价值的想法直接写在报告末尾的"已排除"里并说明原因——排除理由本身是有价值的产出。

## 六、识别伪创新

被问到"这是创新还是补丁"时，查这张表：

| 常见"伪创新" | 为什么不是 | 改判方式 |
|---|---|---|
| 加引导 / 加教程 / 加示例 | 用户仍要做完全同样的事 | 回到任务重构，看能否减少步骤 |
| 加模板库 | 只提供起点，不改变流程 | 若模板能自动带入用户已有数据，才算机会 |
| 加仪表盘 / 统计 | 增加信息，不增加能力 | 除非它直接驱动下一步动作 |
| 把功能挪到侧边栏 / 新标签页 | 只是位置变化 | 仅在可发现性确实有问题时算优化 |
| AI 自动生成 X | 若用户最终仍要全部重写 | 看"用户是否愿意直接采用"，不能采用就不算 |
| 加积分 / 成就 / 打卡 | 与核心价值无关 | 减法候选 |

另外三条纪律：

- 不要因为竞品有，就推断"我们也应该有"。
- 不要提出需要改变定位的方案却不标 L3。
- 不要把机会写成功能清单（"增加导入、增加模板、增加统计"是清单，不是机会）。

## 七、与方向探索的分工

- **04 产出机会卡片**：局部、可独立验证、通常对应一次 L1/L2 改动。
- **07 产出方向**：把多张卡片聚成一条路线，比较取舍，通常对应 L3。
- 04 不做方向比较（会把机会强行拔高）；07 不重新发明机会（会重复劳动）。方向探索时先用 04 生成素材，再进 07 收敛。

## 退出条件

- [ ] 3-6 张机会卡片，字段齐全，每张都有反证条件
- [ ] 至少一个跳出当前形态的方向，至少一个减法方向
- [ ] 已排除项及原因已记录
- [ ] 全部标 E3，未伪装成结论

## 常见失败

- 所有机会都是"加引导、加模板、加仪表盘" → 本质仍是补丁，不是创新。
- 只从自己熟悉的技术出发想方案 → 与用户任务脱节。
- 没有反证条件 → 无法被证伪，后续永远"看起来都对"。
